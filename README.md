## Ответы на вопросы
1. **Чем `int.TryParse()` безопаснее `int.Parse()`?** `int.Parse()` выбрасывает исключение и аварийно завершает программу в случае некорректного ввода (например, букв). `int.TryParse()` возвращает логическое значение (`false`), позволяя корректно обработать ошибку. `int.Parse` стоит использовать, только если мы на 100% уверены в валидности строки.
2. **Когда `switch` удобнее, чем цепочка `if/else if`?** Когда происходит сравнение одного значения со множеством константных вариантов. Пример из жизни: обработка нажатий клавиш в меню или выбор действия по коду ошибки.
3. **Что произойдёт в `switch`, если убрать `break` после одного из `case`?** В C# компилятор выдаст ошибку сборки, так как «проваливание» из заполненного `case` в следующий запрещено (за исключением пустых сгруппированных `case`).
4. **Чем отличается `=` от `==` в C#?** `=` — оператор присваивания значения переменной, а `==` — оператор сравнения на равенство. Их путаница приводит к синтаксическим ошибкам.
5. **Можно ли написать тернарный оператор внутри другого тернарного оператора?** Да, можно (вложенные тернарные операторы). Пример из шага 5: `string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`. Читаемость такого кода резко падает при увеличении уровней вложенности, поэтому им не стоит злоупотреблять.

## Главные выводы
1. Использование безопасных методов приведения типов вроде `int.TryParse` предотвращает падение программ от неверных действий пользователя.
2. Группировка условий с помощью логических операторов делает код компактнее, заменяя громоздкие каскады вложенных условий `if`.
3. Современный синтаксис паттерн-матчинга в `switch` существенно повышает читаемость кода при комплексных проверках диапазонов значений.
